# 手机版 UI 设计与实施

2026-10-18：用户指定 Claude 设计 UI，Codex 实施。设计来自 [Claude 会话](https://claude.ai/chat/b0b72419-2f2f-469c-a52c-c78d335d6d98)，原始可交互稿保存在 [claude-prototype.html](../mobile/design/claude-prototype.html)。原稿使用演示数据，不能当作产品运行或片源可用证据。

## 已采用的方案

- 「放映厅」视觉：墨黑 `#0C0D11`、暖白 `#F2EEE5`、琥珀 `#F2B457`。原始 token 在 `mobile/tokens.css`，图标路径从 Claude 原稿提取到 `mobile/icons.js`，系统中文字体，不请求网络字体。
- 底部三个去向「发现、直播、记录」，右下角单独搜索。首页有观看记录时先显示继续观看，点击直接读取来源并续播；没有记录时不填演示内容。
- 海报保留一个评分角标，说明改为年份/类型；顶部分类与评分入口分层。豆瓣和 MDBList 继续使用现有可播检查逻辑。
- 详情按影片信息、来源、测速、选集排列。来源改为纵向选项；超过 30 集分段。点击集数先选择，再由底部固定按钮播放。
- 中央圆形播放键，三秒自动隐藏控制栏，点画面呼出；左右双击各跳十秒，保留进度细线。倍速、选集、换源放入设置面板；横屏面板占右侧约 30%，返回先收面板再退出播放器。
- 直播新增频道名搜索和仅高清筛选（至少 720P，另保留 1080P 分组），保留换台和备用线路。线路数来自实际配置，不生成节目单。
- 缓存归入记录页，说明仅保存片单、评分和海报。快照超过 30 天显示实际日期和本地版更新方式。

## 实施入口与边界

`mobile/index.html`、`mobile/mobile.css`、`mobile/mobile.js` 是手机页面输入；`mobile/bridge.js` 在共享业务闭包中公开有限的手机交互方法。`scripts/assemble-mobile.py` 通过受检替换组装 `app/public/mobile/`。不要直接维护生成文件，也不要为手机外观修改 TV 样式。

Claude 原型中固定的三个来源、示例评分、演示海报和故障次数均未带入实际应用。主界面从真实接口和本机记录读取数据。

以下是原型建议而非本次已实现能力：拼音首字母搜索、点播断流自动换源、测速后自动改变用户所选来源。当前仍支持既有别名/近似片名搜索、手动选最快来源及直播自动尝试备用线路。不能在交接或发布说明中把原型建议写成已完成功能。

## 验证口径

本机浏览器检查了 320/360/430/480 像素竖屏、932×430 横屏，主要触控目标不小于 44px；本地 HLS 实际解码，覆盖选集、测速结果、快进快退、双击跳转、进度、倍速、继续观看、直播搜索/筛选/换台/换线路和缓存入口。五种状态通过测试接口模拟：加载、无结果、来源失败、播放失败、快照陈旧。

本轮浏览器控制环境拒绝系统全屏请求，界面显示旋转手机的回退提示；系统全屏、软键盘、后台生命周期和所有真实片源仍需小米手机实测。模拟接口和本地测试视频的通过不代表公网片源可用。具体构建及设备边界见 [MOBILE.md](MOBILE.md)。
