beta12 优化现有点播源排序与默认选择。`mobile/source-ranking.js` 统一详情和设置排序：抽测可用且流畅 > 未测 > 慢/明显波动/多次播放失败或卡顿/用户标广告 > 测速失败；同层内先按语言与地区推断原声偏好，再按已知分辨率（1080P 封顶收益），再比较速度、连接耗时与播放历史。语言后缀覆盖通用字段，多语言和多地区不武断判为原声。测速读取 HLS 声明码率并保留 35% 带宽余量；缺少码率按分辨率估算，均为启发式而非全片流畅保证。连续成功播放会保存实际解码尺寸，区分“实播”“列表标注”“未知”。

beta13 按用户要求增加点播自动换源并恢复进度。`mobile/failover.js` 在首次加载 20 秒无进展、实际播放 12 秒无进展或明确播放错误时，按既有质量排序选择同组同集备用记录；每次播放最多尝试 3 个不同备用记录，排除当前/已尝试/测速失败者。详情请求 10 秒超时，缺集不代用末集；恢复时若目标超过新时长或总时长相差超过 max(60 秒,10%)，跳过该版本。保留秒数和倍速，历史恢复/用户拖动后尚未出画面就失败也保留目标时间。片头、广告和剪辑差异仍可能造成内容时间点偏差，不宣称语义对齐。

恢复请求由会话与播放标记隔离，返回、手动选源、新播放和进入直播取消旧请求；HLS 迟到错误不作用于新播放。主动暂停、后台、明确离线不启动新的恢复尝试。恢复中及失败耗尽不会触发下一集；结束后提示手动选源。直播沿用原线路恢复逻辑。beta12 的“播放中不自动换源”由此后续要求取代，手动选择正常播放时仍保留。

16 类回归检查通过，涵盖候选排序、同集、位置/倍速、预算、缺集、暂停/后台/断网/直播排除、并发失败去重、取消迟到响应、时长不符、首次加载、拖动宽限及连续失败进度。本机浏览器以实际 640×360 HLS 在 11.30 秒注入原生 error 事件，观察自动切到备用源并从原进度继续到 25.04 秒，控制台无错误。这是本机模拟故障，不等同手机公共来源实测。证据：`outputs/mobile/beta13-failover-tests.json`、`beta13-browser-validation.json`、`beta13-failover.png`、`beta13-package-validation.json`、`beta13-phone-validation.json`。最终包只改手机 app.js/index.html，后端/依赖/快照与已验证基线一致；用户重连后已成功安装并启动，状态接口 HTTP 200；真实来源自动换源、进度恢复及其他未验项仍待实机确认。

商业化与自有 Jellyfin 片库尚未实施。保留 beta5 自动遮挡实机验收待办，不能因本轮改动而标记遮挡成功。


## 当前产品决定

- 主线是星幕 TV：自带服务端的 Android TV APK，直接在电视运行，不依赖电脑常开。基于 LibreSpark/LibreTV，保留上游 AGPL-3.0-or-later 及第三方声明。
- 手机端沿用自带服务端与本地片库，单独包名、普通桌面入口和 64 位运行库；电视版继续保留。
- 用户重视遥控器操作、韩剧美剧及国产港澳台片源、可播放推荐、缓存速度、央视与高清直播、备用线路和测速。
- FongMi 曾用于早期验证；用户后来明确不满意，不再把它作为主力方案或推荐对标。YouTube 已放弃，暂不续做。
- 已选择公开源码与 APK，品牌为「星幕 TV」，GitHub 仓库为 [liukaixuan1163523145-web/starlight-tv](https://github.com/liukaixuan1163523145-web/starlight-tv)。
- 已加入 Wise 与 PayPal 公开赞助入口，位置为 `.github/FUNDING.yml`、README 和 `docs/assets/paypal-qr.jpg`。赞助是自愿支持，不解锁功能；不把私人银行卡资料加入仓库。
- Claude 负责选型、设计和商业化讨论；Codex 负责实现、配置、构建与验证。策略建议以用户后续决定和已验证实现为准。

## 架构与修改入口

| 要改什么 | 先看哪里 | 注意事项 |
| --- | --- | --- |
| APK 启动、服务生命周期、自动登录 | `android/MainActivity.java`、`ServerService.java`、`start.cjs` | 内嵌 ARM Node + Next standalone，只监听 `127.0.0.1:8080`，应用私有目录保存配置 |
| 解包、数据迁移、包版本 | `android/RuntimeInstaller.java`、`AndroidManifest.xml` | 改 payload 时同时更新运行时 VERSION 和 APK 版本；保留用户配置与数据 |
| 电视导航和页面 | `tv-before-live.js`、`tv/`、`scripts/assemble-tv.py` | 模块与基底是输入；`tv/tv.js` 和 `app/public/tv/` 为组装结果，单改生成文件会被覆盖 |
| 播放、加载提示、遥控器 | `tv/tv-player-controls.js`、`tv-playback-loading.js`、`tv-live.js` | 必须覆盖全屏、焦点、返回防重复、换台和线路切换 |
| 测速与来源选择 | `tv/tv-speed.js`、`tv-speed-integration.js` | 测的是实际媒体片段；播放或切换页面时取消不再需要的测速 |
| 推荐和缓存 | `app/src/app/api/douban/route.ts`、`mdblist/route.ts`、`tv-cache/route.ts`，以及 `tv/tv-recommendation-cache.js`、`tv-cache-center.js` | 本地版必须保持推荐与海报不联网更新；搜索、测速、可播检查和播放仍联网 |
| 点播和直播清单 | `android/defaults.json`、`live-channels.json` | 源有效性是时间与网络相关状态，新增后先验证，不把旧检查当作当前可用证明 |
| 打包和数据快照 | `scripts/`、`local-data-manifest.json`、`runtime-provenance.json` | 按 BUILD.md 操作；数据快照只带白名单公开字段，凭据与观看历史留在本机 |

电视包名仍为 `local.codex.libretvprobe`，这是保留覆盖升级兼容的决定。电视版当前只发布 `armeabi-v7a`，Android 最低 API 28；不宣称所有 Android TV 兼容。电视网页兼容基线为 Chrome 66。手机版另见 MOBILE.md。

## 接下来最有价值的验收

以下是建议顺序，不表示已经执行，也不自动授权新发布或付费操作。

1. **本地版电视复验**：安排覆盖安装 `1.1.2-local`，保留数据；先核对签名与版本，避免卸载导致配置丢失。确认首次导入、冷启动、推荐/海报、搜索与点播、直播、测速、遥控器及退出再开。分别记录首次导入耗时和后续冷启动耗时。
2. **无密钥行为复验**：验证推荐和海报来自本地且不会调用 MDBList；网络恢复后搜索与播放仍可用。旧安装可能保留 Key，但本地版不会把它传给服务端子进程。
3. **兼容范围和数据维护**：在新电视上测试后再扩大支持范围；本地数据更新需重新导出快照、核对哈希并打包，不能承诺自动刷新。
4. **商业化后续**：当前仅落实自愿赞助。安装服务、支持服务和收费功能均未形成已经验证的业务；继续讨论时先核实上游许可义务与所分发数据、片源的授权范围。

每项完成条件：提供对应版本、测试环境、实际观察和证据位置。桌面复制 APK、构建成功、发布成功、电视验收是不同结果，分别记录。

## 构建与发布的容易出错之处

- 构建命令与依赖统一维护在 [BUILD.md](BUILD.md)，不要在交接文件再复制一份容易过期的命令流程。
- 正式包 `debuggable=false`，不能假设可用 `adb run-as` 写入配置。保留原签名以覆盖安装；签名文件、密码、API Key 不进 Git、APK 或交接正文。
- 项目本地 `publication` remote 指向当前发布账号；`origin` 留有旧暂停账号。每次推送先核对，使用当前发布账号；保持低频、串行操作，失败先查原因，避免重复请求。
- 发布源码、APK 与数据清单需对应；赞助文档修改不表示已重建 APK。
- 后续已制作手机版并更新交接；电视安装及 GitHub 发布状态保持原记录。
